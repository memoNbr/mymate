What mind built: a cognitive agent in Python

20-minute lesson · mission: understand the brain in our crew & sim · no deep dives, code first.

The one-sentence version

A chatbot answers one question. A cognitive agent lives in a loop: it sees something, updates what it believes, scores what it could desire, commits to the strongest one as an intention, acts, reflects, and saves what it learned — so next time it starts smarter than it was.

That loop — belief → desire → intention → act → reflect → persist — is literally what cogarch_bootstrap.py (written by crew agent mind, 249 lines, stdlib only) does. Let's read it as a story, not as code.

Part 1 · The loop, in one picture

   observation ──> perceive()        ──> beliefs (what agent thinks is true)
                      │
                      ▼
                 score desires       ──> observe .5 / explain .8 / decide .9
                      │
                      ▼
                 commit strongest    ──> intention (the one thing it'll do now)
                      │
                      ▼
                 act (your hook)     ──> "I commit to the goal and will act now"
                      │
                      ▼
                 sample + trust      ──> trust = 0.6×conf + 0.4×priors
                      │
                      ▼
                 save()  ───────────> priors+memory to cogarch_state.json

The loop breathes every --cadence seconds. Small loop, big idea: this is the same shape as the cabin sim's bdiReason — the seat/avatar agent deciding to respond to your ride.

Part 2 · Desires are manufactured, not felt

The agent doesn't "get feelings". It has a goal table with preconditions and scores:

GOALS = {
  "observe": {"pre": lambda self: True,              "desire": lambda self, obs: 0.5},
  "explain": {"pre": lambda self: bool(self.beliefs.get("primes")), "desire": lambda self, obs: 0.8},
  "decide":  {"pre": lambda self: True,              "desire": lambda self, obs: 0.9},
}

Each cycle it checks each goal: is it allowed (pre)? and how badly do I want it (score)?. The highest-scoring valid desire becomes this cycle's intention. That's BDI: beliefs decide what's possible, desires are ranked, intentions are commitments.

Part 3 · Memory so it isn't a goldfish

Two layers of "remembering":

  • Working memory — the last 8 observations, kept in the process (self.memory).
  • Long-term priors — save() writes priors + beliefs + memory + intention to cogarch_state.json; _load() reads it at boot. Restart the agent tomorrow and its trust and ride count are still there.

Part 4 · Trust: learn without swinging

def update_trust(self, s):
    self.trust   = 0.6 * s["conf"] + 0.4 * (self.priors.get("trust", 0.5))
    self.priors["rides"]  += 1
    self.priors["trust"]   = round(self.trust, 3)

New evidence counts 60%, carried history 40% — an EWMA blend. In the demo run it drips upward (0.500 → 0.530 → 0.572): it adapts, but doesn't panic on one weird sample.

Part 5 · Any brain, one wire

llm_call() speaks exactly one dialect: POST {base}/chat/completions with a Bearer key. That single format works across OpenAI, ollama, llama.cpp, vLLM, Gemini's /openai surface, Groq. Config precedence is schoolbook-clean: defaults < .ini < environment < CLI flags.

The quiz — did it stick?

Q1 · What makes an agent "cognitive" and not a chatbot?

  • It calls one huge model
  • It runs a memory loop
  • It uses a bigger corpus
  • It streams its answers

Q2 · In BDI, what does the agent commit to?

  • A random desire
  • The strongest desire
  • The cheapest action
  • The newest belief

Q3 · What does save() give the agent across restarts?

  • Its past priors
  • Its full source
  • Its model logs
  • Its network run

Q4 · Why blend trust with priors at 60/40?

  • To slow each cycle
  • To score the LLM
  • To stay adaptive
  • To hide the state

(Answers: Q1 runs a memory loop · Q2 the strongest desire · Q3 its past priors · Q4 to stay adaptive.)

Where the cabin sim fits (the "so what")

The lesson's architecture isn't academic for us: the crew's cabin agent reasons through the same belief → desire → intention shape (bdiReason) to decide how the digital passenger responds to seat ride events. `cogarch_bootstrap.py` is that brain in its cleanest, model-agnostic form.
